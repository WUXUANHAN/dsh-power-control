# 桌面版教程：重启 / 关闭按钮

这篇是给**用桌面客户端（DeepSeek Harness.exe）的人**看的。网页版（`npx @deepseek-ai/dsh web`）同样适用，只是"从开始菜单重开"换成重跑命令。

---

## 0. 先确认它装好了

打开 **设置 → 插件**（左侧「插件」页也行），列表里找 `dsh-power-control`：

| 应该看到 | 说明 |
|---|---|
| 状态：已启用 | 关闭状态不会有按钮 |
| 来源：`git+https://github.com/WUXUANHAN/dsh-power-control.git` | 也可以是从本地目录装（`link:`），功能一样 |
| 详情页标题：**电源控制** | 点进去有完整说明和图标 |

这一行在就说明装好了，不用再装第二遍。

---

## 1. 按钮在哪

![按钮位置](desktop-guide.png)

一句话：**会话标题栏最左边，紧挨侧边栏分隔线**。

- 分隔线左边那一列是侧边栏（品牌、新会话、会话列表），**打开/收起侧边栏的按钮在那一列里**；
- 分隔线右边就是会话标题栏，第一个位置就是插件挂的两个按钮；
- 再往右才是会话标题，所以按钮永远在**标题左边、侧边栏开关右边**。

两个按钮都是 28×28：

| 图标 | 含义 | 颜色 |
|---|---|---|
| 环形箭头 ↻ | 重启 DeepSeek Harness | 灰色 |
| 电源符号 ⏻ | 关闭 DeepSeek Harness | 红色（危险操作提示） |

> 侧边栏收起时（宽度小于 1024 会自动收起），左边那一列会整个消失，两个按钮仍在会话标题栏最左边，位置不变。

---

## 2. 重启：完整流程

1. 点环形箭头 → 弹出确认框 **「重启 DeepSeek Harness？」**
2. 读一下正文：会说明"当前正在运行的任务会被中断，重启完成后本页自动刷新"
3. 点 **立即重启**（或按 Esc / 点遮罩取消）
4. 页面被一层状态遮罩盖住，显示 **正在重启…**
5. 等 10～20 秒，程序退出、重新启动、页面自动刷新回会话

**时间线**（点下确认之后）：

| 时刻 | 发生什么 |
|---|---|
| 0 s | 页面 POST 给宿主，宿主派发一个**独立进程**的 PowerShell 脚本，立刻返回 |
| 1.2 s | 脚本开始动作：先对所有 `DeepSeek Harness` 进程调 `CloseMainWindow()`（正常关窗，让会话落盘） |
| 5 s | 还活着的进程 `Stop-Process -Force` 兜底 |
| 6 s 左右 | 重新 `Start-Process` 启动程序 |
| 10～20 s | 新进程起来，页面轮询到 `/status` 能通 → 自动 `location.reload()` |

为什么不直接在本进程里关？因为杀进程那一刻宿主自己也会死，动作必须交给一个能"活过父进程"的脚本。

---

## 3. 关闭：完整流程

1. 点电源符号 → 确认框 **「关闭 DeepSeek Harness？」**
2. 点 **立即关闭**
3. 遮罩显示 **正在关闭…** → 进程退出后变成 **DeepSeek Harness 已退出。**
4. 这时页面已经连不上任何东西，可以直接关掉窗口
5. 想再用：从**开始菜单**重新打开（或桌面快捷方式）

⚠️ 和"点窗口右上角 ×"的区别：这里是真的**完全退出**（连托盘一起），不是最小化到后台。

## 4. 更新这个插件

现在是 Git 源安装，**改了本地文件不会自动生效**。流程：

```sh
cd dsh-power-control
# 改代码 → 自测
npm test
# 提交并推送
git add -A && git commit -m "feat: ..." && git push
```

然后在 **设置 → 插件** 里对 `dsh-power-control` 点**重装 / 更新**（或命令行 `plugin_manager install_bundle` 用 `github:WUXUANHAN/dsh-power-control`）→ 最后**重启 DSH**（正好可以用新加的按钮 😄）。

只改 `client.js`（按钮长相、文案）时，宿主半边没动，刷新页面（`Ctrl+R`）一般就能看到；改了 `index.js`（宿主路由、重启逻辑）必须重启。

---

## 5. 卸载

**设置 → 插件 → dsh-power-control → 卸载**。卸载后按钮立即消失，`%TEMP%\dsh-power-control\` 里的日志可以手动删。

## 6. 出问题先看这里

| 现象 | 怎么办 |
|---|---|
| 插件显示已启用，但标题栏没按钮 | 按 `Ctrl+R` 刷新页面（换安装来源后常需要一次） |
| 点了没反应，也没有确认框 | 打开 `%TEMP%\dsh-power-control\restart.log` 看有没有新行；没有就是请求没到宿主 |
| 确认框出来了，点了"立即重启"却一直转 | 看日志里的 `running:` / `remaining:` / `relaunched` 三行，`relaunched` 缺失 = 启动命令解析错，去 `/dsh-power-control/api/status` 看 `launch.exe` |
| 重启后程序没回来 | 从开始菜单手动打开一次；日志里 `exe 不存在，没有重启` 说明路径不对 |
| 关掉后想确认真的没了 | 任务管理器搜 `DeepSeek Harness`，应该 0 条 |
| 遮罩卡住不动 | 直接 `Ctrl+R`；程序其实早已重启完成 |

**日志位置**：`%TEMP%\dsh-power-control\`
（`restart.log`、`shutdown.log`，以及每次生成的动作脚本 `restart-*.ps1`）

## 7. 常见问题

**会丢会话吗？**
不会丢历史。会话按会话落盘，重启后左侧列表还在；但**正在跑的任务**会被中断，不会自动续跑。

**能只关窗口、保留后台吗？**
不能。这个按钮的语义是"完全退出"。只想收进托盘请点窗口的 × 或最小化。

**为什么要点两次？**
第一次点开确认框，第二次才是真的执行。这是故意的——重启/关闭都会打断你正在做的事。

**有没有更安全的验证方式？**
有。用环境变量 `DSH_POWER_CONTROL_DRY=1` 启动 DSH，脚本只往日志写一行 `dry-run` 就退出，不动进程。适合排查"按钮到底有没有把请求发出去"。

**能改启动的程序吗？**
能，环境变量 `DSH_POWER_CONTROL_EXE` 指定要拉起的 exe；不设时按 `process.execPath` 自动判断（桌面版就是 `DeepSeek Harness.exe`）。
